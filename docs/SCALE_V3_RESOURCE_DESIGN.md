# Resource and execution design for a fresh six-world comparison

Status: implementation reviewed, 2026-09-10; the exact full-run registration is still pending. The service-based startup qualification failed before native HELLO in a different AppArmor launch context. Its failed slot, skipped slots and uncertain cleanup remain historical evidence. A harmless caller-scope probe supports the alternative launch context; it does not establish Hermes startup reliability, whole-world capacity or complete cleanup. The separately registered v3 scope startup qualification has now returned nine passing slots; its independently reviewed raw outcome is a mandatory prerequisite for the full campaign.

Use **one caller-launched systemd user scope around the complete campaign supervisor**, with at most two worlds active. All descendants then share the same envelope: the supervisor directly starts the world controllers and the MiroFish application; controllers start Hermes/bubblewrap, and MiroFish starts OASIS. Existing direct-parent, private socket and simulation-identity checks can remain in place. Separate world and service scopes would require additional ownership adapters without answering the user's scientific question.

Scope mode inherits its caller's execution environment. A scope groups externally created processes and has no application MainPID or native exit-status meaning. These are documented semantics; the harmless host probe separately observed the caller process executing into its controller. Retain that distinction in the new proof. See the primary [systemd-run documentation](https://raw.githubusercontent.com/systemd/systemd/v255/man/systemd-run.xml) and [scope documentation](https://raw.githubusercontent.com/systemd/systemd/v255/man/systemd.scope.xml).

The minimum implementation has four parts:

1. **A fixed outer launch and release gate.** Bind campaign/source/dependency hashes, unique scope and InvocationID, ControlGroup, controller PID/start ticks/UID/boot, ancestry, exact argv/cwd and observed security context before permitting native work. Scrub the caller environment before scope launch; retain real provider credentials only through existing private configuration, never unit metadata or public receipts. The full campaign needs provider networking and its isolated MiroFish origin. Do not copy the startup-only dummy credentials and disabled-network namespace into the full experiment. Preserve Computer's private pipes and canonical native commands.

   The controller writes its inner result and stays alive while the outer observer retains terminal evidence. Release it only after world/service cleanup and a membership check leaving only that controller. Record its actual return and caller wait status. A collected scope or a successful scope Result cannot substitute for native exit zero. Missing membership reads remain unknown. No arbitrary-command or generic unit-management framework is needed.

2. **One preregistered shared resource ceiling.** The proposed envelope is four CPU equivalents, 12 GiB memory, 512 tasks and zero swap. Check actual kernel controls before the work gate, including cpu.max's period, and retain scope resource-event observations when available. A small harmless probe and a 4 GiB startup qualification do not establish whole-campaign capacity. These limits still require prospective review and current-boot readbacks.

   Both arms share the ceiling and MiroFish. There is no per-world fairness, separate service reservation or guaranteed I/O protection. Longer SkillOpt work can contend with its peer; CPU throttling can increase elapsed time. Memory pressure or an OOM can interrupt multiple worlds. Record those as execution constraints with preserved costs, not employee quality scores. Do not change resources after seeing outcomes.

3. **Three fixed pair waves and existing inner cleanup.** Run 211 no-learning/SkillOpt, then 307 SkillOpt/no-learning, then 401 no-learning/SkillOpt. Both worlds in a wave must finish their cleanup before the next starts. Replace the current rolling refill only; keep the established independent world observation/cleanup threads. A nonzero native exit, observation/deadline failure, unconfirmed cleanup or service failure stops further dispatch and triggers bounded cleanup of active work. Every planned slot remains visible; no replacements, retries or outcome-conditioned schedule changes.

   Each world's clock begins at dispatch, retaining its 24-hour ceiling, 150-second employee startup bound, per-task/per-epoch limits and 120-second world cleanup. Service startup/cleanup retain 120/30 seconds. The prospective inner campaign ceiling is 3 × (86,400 + 120) + 120 + 30 + 600 = **260,310 seconds**. The 600 seconds is bounded orchestration allowance. An additional 180 seconds is reserved for outer cleanup, giving a 260,490-second scope runtime backstop and a five-second stop escalation. This is ceiling arithmetic, not a forecast or a guarantee that learning fits.

   First request cooperative interruption of the verified supervisor so it can close each exact simulation while the shared service remains alive. Stop the whole scope only as the bounded final fallback; killing MiroFish first would destroy the normal actor-cleanup path. Retain both inner receipts and final scope closure. A forced cleanup cannot turn failed inner evidence into a completed study. Parent death or a new boot leaves missing terminal evidence and uncertain in-flight costs, without resume.

4. **A small new registration/audit adapter.** Keep historical v2 sources and acceptance unchanged. New files should freeze the shared envelope, fixed waves, new prerequisite/source bindings and startup-observability flag, then reuse the existing native runner and process helper. The outer gate must be required before the inner supervisor accesses credentials or starts the service; there must be no independent inner CLI bypass. The new auditor adds whole-scope ownership/resources/closure and wave timing to the existing per-world source, raw work/gate, costs, reporting and lifecycle checks. Resource counters never replace token receipts.

The scientific configuration remains six fresh worlds and three complete paired seeds, paired byte-identical 25-person cohorts, four enterprises/twelve employees/eight consumers/one agency, twenty action days plus settlement, skill-transfer state, all employees, T2/V2, contrastive K2, edit budget four and boundaries 3/7/11/17. Day 3 remains ineligible under unchanged release rules. Enable startup observability in both arms and all replays. Missing diagnostic stages must not be scored as bad employee answers.

Retain fixed initial/benchmark fulfillment before the action horizon as primary, with 240 fixed commitments per world. All-demand fulfillment, utility, adoption and prospective deployed-version exposure remain secondary. Keep the existing campaign caps: 1,440 online sessions, 108 learning epochs, 1,296 target replays, 44,640 employee/optimizer calls, 792 million charged tokens and 3,972 contracted actor requests. Bootstrap/social inference remains outside that meter. Require all six valid completed worlds, all three pairs and accountable cleanup before the primary comparison; partial prefixes and reservations remain separately reportable. Three reused development pairs are descriptive evidence. No adoption or positive improvement is required, and historical worlds cannot fill missing new slots.

Before registration, test changed scope/controller identity, missing controls, inherited-environment rejection, caller versus native exit, GC before evidence retention, ownership escapes, deadlines, fixed wave barriers, failure halt, unchanged learning configuration and refusal to publish a subset. Then review the separate scope qualification and exact full-run source/prerequisite binding. This document does not certify native readiness.
