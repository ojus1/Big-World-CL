# Native tool readback audit correction

The registered six-slot Hermes preflight completed in 289.124 seconds with
64 physical requests, 631,022 measured tokens, complete accounting and confirmed
cleanup. Every slot loaded the native skill, submitted an immutable artifact to
the trusted grader, read it again and produced a subsequent native response.
Four submissions passed every work-quality check; the two incident submissions
were rejected. Those semantic outcomes are separate from transport capability.

The original preflight report records **zero capability passes**. Its auditor
required each tool response to be one complete JSON document. The actual pinned
Hermes harness appended an idempotent-read warning after the JSON response when
the requested post-submission read returned the same contents for the second
time. All six readbacks had this exact native suffix. The old parser therefore
failed to recognize valid readbacks in both streaming and nonstreaming slots.

`scripts/audit_hermes_readback_v2.py` is an additive, post hoc audit correction.
It first requires the original full six-slot integrity audit to pass at its
matching source revision and separately registered manifest hash. It then:

1. Checks the pinned Hermes revision, unchanged tracked Python, and exact native
   warning formatter/executor source hashes.
2. Accepts plain JSON or the exact native idempotent `read_file` warning, with
   its stated repeat count independently reconstructed from identical earlier
   call arguments and returned contents.
3. Verifies that the read follows the trusted `work.commit` response, matches the
   actual submitted artifact, and is followed by a native final response.
4. Retains the original usage, cleanup, semantic outcomes and capability
   verdict alongside the corrected result.

It does not ignore arbitrary suffixes, accept a warning as a substitute for file
contents, count an unproven repetition, accept boolean/numeric substitutions, or
alter raw sessions, receipts, reports or historical source. Thirteen focused
tests cover these cases and compile the actual pinned pure formatting function
for parity. CI checks out that source without installing or running Hermes.
Independent review reproduced all thirteen tests, the full corrected audit,
all 289 original regular-file hashes, the public result projection and the
42-process absence check. No original artifact was changed.

The corrected audit recognizes all six native capability slots. The initial
preregistration, original false capability verdict and correction remain visible
in [the observation](hermes-preflight-observation-v1.json). This is a component
compatibility finding, not an estimate of long-horizon reliability, learning
gain, or business performance. The native harness does not record a per-request
hash tying every provider response to a conversation message; continuation is
inferred from the pinned native trajectory, not independent wire authentication.

The warning is generated by the pinned upstream
[guardrail formatter](https://github.com/NousResearch/hermes-agent/blob/2c8a2b65aa148ceb178d2251c54a523af12092c9/agent/tool_guardrails.py)
and appended through the native execution path. Repeating a read was required
by this component fixture to verify the submitted file; no native action needs
to be replayed to repair this audit interpretation.

```bash
MiroFish/backend/.venv/bin/python scripts/audit_hermes_readback_v2.py \
  /path/to/original/hermes-transport-preflight-v1 \
  --manifest-sha256 ea5e5e66be002a3f497d24c7bc2b60a85312e9174e84e323f0c5b154633da0f4
```

The source and dependency checks require the matching integrated checkout and
the same Python runtime as the native registration. Raw evidence remains
private. A later process recheck found all 42 recorded owned process identities
absent; this is separate from the captured cleanup receipts.
